## Що об’єктивно не можна позначити завершеним

1. Два додаткові реальні клієнтські кейси: немає назв, URL, ролі, матеріалів і дозволів. Мінімальні три чинні кейси не підмінюють ціль п’ять.
2. Повна особиста біографія, юридичні/профільні поля та універсальний гарантійний строк: потрібне підтвердження власника. Публічна редакційна відповідальність і процес уже є.
3. Публікація профілів/відгуків/клієнтських credit та PR: потрібні акаунти, точні бізнес-факти, згода клієнтів і явний дозвіл на надсилання підготовлених повідомлень. Цілі на 90 днів не видаються за отримані backlinks.
4. Післярелізна індексація, усунення перетинів у фактичному Google, KPI 14–240 днів, клієнтські before/after конверсії й польові CWV: потрібні наступні зіставні періоди та доступні дані. Два перекривні дорелізні вікна не є ефектом релізу.
5. Немає доступного Admin API для прямого зіставлення GA4 stream ID з measurement ID; report stream/hostname і єдиний тег на сайті перевіряються окремо. Приватний dashboard не має підтвердженого browser visual QA через адміністративну policy-перевірку.

## Межі архітектури

Сайт фактично статичний і публікується на GitHub Pages. Next.js routes із формулювання ТЗ зіставлені з реальними HTML routes; міграція платформи не потрібна для цих змін. Старі підтримувані alias-сторінки лишаються noindex/canonical, а не удаваними HTTP 301. При майбутній зміні edge/hosting застосовується чинний redirect contract і окремий план; в цьому релізі DNS не змінюється.

Інші сервісні сторінки мають спільні пояснення процесу; inventory зберігає сигнали їхньої схожості. Це не приховано й не оголошено Google-канібалізацією. Автоматично зливати або видаляти їх без SERP/GSC-підстав не можна.
