# ТЗ: індексація міського SEO-кластера MAX SITE

## 1. Мета етапу

Підготувати 20 міських сторінок MAX SITE, які зараз закриті через `noindex`, до безпечної індексації Google. Сторінки мають відповідати локальному комерційному наміру, давати користувачу корисну інформацію та не виглядати як doorway-сторінки з механічною заміною назви міста.

Основний домен: `https://maxsite.com.ua`.

Репозиторій: `Emelkey/Max-saite`.

Сайт «Формула Чистоти» не входить у цей етап і не змінюється.

## 2. Причина робіт

Google Search Console показує 20 URL із причиною «Індексування сторінки заборонено тегом noindex». Це очікувана поточна конфігурація: сторінки були навмисно закриті, доки не отримають достатньо унікальний зміст. Просте видалення `noindex` без доопрацювання створює ризик слабких, дубльованих або doorway-сторінок.

Окремий запис «Варіант сторінки з тегом canonical» потрібно перевіряти за конкретним URL у Search Console. Якщо canonical веде на правильну основну сторінку дубля, це не є помилкою.

6. У GA4 ресурсу MAX SITE позначити `click_phone` і `generate_lead` як ключові події.
7. Зв’язати GA4 MAX SITE з Google Ads та імпортувати обидві ключові події як конверсії. Не створювати дублікати конверсій.

9. Зв’язати Search Console `https://maxsite.com.ua/` з GA4-ресурсом MAX SITE `548154976`.

### Правило безпеки рекламного запуску

Кампанію можна підготувати повністю, але її ввімкнення має відбуватися тільки після перевірки платіжного профілю, денного бюджету та того, що оптимізація використовує конверсії саме GA4-ресурсу MAX SITE `548154976`. Якщо Google Ads показує інший GA4-ресурс, запуск зупинити до виправлення зв’язку. Роботи не повинні змінювати кампанії «Формули Чистоти».

## 4. Вимоги до кожної міської сторінки

### Технічне SEO

- один унікальний `title`;
- один унікальний `meta description`;
- рівно один `H1`;
- `meta robots: index, follow`;
- self-referencing canonical на HTTPS-URL сторінки;
- `og:title`, `og:description`, `og:url` відповідно до сторінки;
- один Google tag ресурсу MAX SITE `548154976`: `G-TS8DMMKK34`;
- валідні JSON-LD: `Organization`, `Service`, `BreadcrumbList`, `FAQPage`;
- коректний `areaServed` без заяви про неіснуючий офіс;
- сторінка має бути в `sitemap.xml`;
- усі внутрішні посилання мають відкриватися.

### Контент

- унікальний вступ про задачу сайту для бізнесу конкретного міста;
- окремий блок із релевантними типами бізнесу;
- пояснення вибору між лендінгом, багатосторінковим сайтом, магазином і програмою;
- локальна SEO-логіка без масового створення однакових районних сторінок;
- перелік робіт, етапи та актуальні стартові ціни;
- 4 видимі FAQ, зміст яких збігається з `FAQPage` schema;
- CTA на заявку, телефон і Telegram;
- посилання на основні послуги, портфоліо, контакти та суміжні міста;
- жодних вигаданих адрес, офісів, рейтингів, кейсів або гарантій позицій у Google.

## 6. Sitemap і правила індексації

- додати 20 доопрацьованих URL у `sitemap.xml`;
- встановити `lastmod` датою фактичної зміни;
- не додавати до sitemap дублікати та службові сторінки;
- зберегти `noindex` для `404.html`, `privacy.html` і legacy-дублів із canonical на основні URL;
- не змінювати `robots.txt`, якщо він уже дозволяє сканування та містить правильний sitemap.

## 7. Перевірка перед публікацією

- автоматичний SEO-аудит проходить без помилок;
- усі URL із sitemap мають title, description, canonical, index і один H1;
- title та description не дублюються;
- JSON-LD парситься;
- внутрішні посилання не биті;
- `404.html` залишається `noindex`;
- production-пакет збирається для `https://maxsite.com.ua`;
- форми зберігають Telegram fallback і production endpoint;
- `git diff --check` не знаходить помилок форматування.

## 8. Порядок публікації

1. Реалізація в окремій робочій гілці.
2. Локальний аудит і перегляд змін.

4. Після production-деплою повторно надіслати sitemap у Search Console.
5. Запустити перевірку виправлення для групи `noindex`.
6. Запитувати ручну індексацію лише для пріоритетних сторінок, а не всіх URL одночасно.
