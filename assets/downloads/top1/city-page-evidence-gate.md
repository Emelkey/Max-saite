# Доказовий шлюз перед публікацією сторінки міста

MAX SITE · 10.09.2026 · чекліст якості, не гарантія локального ранжування.

Міська сторінка потрібна, коли вона відповідає окремій задачі й має корисні відмінності. Заміна назви міста в шаблоні не створює локального доказу. Обслуговування міста не означає наявність офісу.

## Намір та реальне покриття

1. [ ] Записати місто, майбутній або існуючий URL, основний намір, власника рішення й дату: ___.
2. [ ] Підтвердити, що бізнес фактично працює з клієнтами міста; зберегти дозволене джерело.
3. [ ] Уточнити формат: дистанційна робота, виїзд або справжнє місце приймання. Не підміняти одне іншим.
4. [ ] Вказати реальні обмеження послуг, графіка, виїзду, логістики чи передачі матеріалів; не додавати їх за аналогією з іншим містом.
5. [ ] Перевірити запити в доступному GSC або зафіксованій SERP-вибірці: країна, мова, пристрій, дата й метод.
6. [ ] Пояснити відмінність від національної послуги та сусіднього міста. Якщо її немає, розглянути один корисний хаб.

## Контент і довіра

7. [ ] Надати власний приклад задачі, процесу або дозволений кейс, доречний місту. Чужий кейс не називати місцевим.
8. [ ] Підтвердити права на фото, логотипи й відгуки; не створювати вигаданого клієнта для заповнення секції.
9. [ ] Не публікувати місцеву адресу, карту, координати або LocalBusiness-офіс без підтвердженого місця роботи.
10. [ ] Перевірити телефон та контактні сценарії; код номера не є доказом офісу.
11. [ ] Описати, що саме отримує клієнт, які дані потрібні на старті й як приймається результат.
12. [ ] Додати відповіді на реальні локальні питання, якщо вони є; не переносити однакові FAQ з підстановкою міста.
13. [ ] Перевірити цифри, ціни, строки й обіцянки. Кожна має джерело або чітко позначений статус попередньої оцінки.
14. [ ] Порівняти з сусідніми сторінками змістовно: відмінність заголовка сама по собі не знімає дублювання.

## Технічне рішення

15. [ ] Призначити основний URL наміру, self-canonical та видимі title/H1, що відповідають реальному змісту.
16. [ ] Перевірити schema: Organization/Service не містять вигаданого офісу, відгуку або географічного результату.
17. [ ] Прив’язати сторінку до послуги, доречного кейсу й хаба; переконатися, що до неї є змістовний внутрішній вхід.
18. [ ] Перевірити мобільне меню, CTA, форму, відсутність переповнення й доставку погодженого тесту.
19. [ ] Узгодити статус: готова до індексації / доопрацювати / залишити в чернетці. Кількість міст у ТЗ не замінює доказів.
20. [ ] Для вже опублікованого URL не застосовувати noindex, merge або видалення без аналізу GSC, лідів, backlinks і погодження.
21. [ ] Додати до sitemap лише indexable canonical URL з HTTP 200; чернетки й альтернативи не домішувати для збільшення кількості.
22. [ ] Записати рішення, незакриті умови, джерела та дату повторного перегляду. Публікація не доводить індексацію або приріст.
